# Experiment Plan

**Problem**: 基于最新手稿 `drafts/LAATDraft_v1.3.tex`，构造一个最简单的低空单层三区域流量规划与闭环控制实验，验证静态规划、MFD 目标构造、起飞与边界反馈、谱半径稳定性判据之间是否闭合。  
**Method Thesis**: 若三块低空区域的静态聚合通量守恒，目标位于 MFD 自由流分支，执行流不饱和，且区域间转移矩阵 `B` 满足 `rho(B)<1`，则目标累积量应成为闭环活动子系统的局部指数稳定均衡。  
**Date**: 2026-05-30  
**Manuscript Source**: `drafts/LAATDraft_v1.3.tex`

## Claim Map

| Claim | Why It Matters | Minimum Convincing Evidence | Linked Blocks |
|-------|----------------|-----------------------------|---------------|
| C1: 静态规划到动态目标的桥接是自洽的 | 手稿核心不是复杂微观航路，而是守恒通量、固定路由比例、MFD 目标和执行控制之间的闭环 | 三区域路径流聚合后满足逐区域守恒；`Lambda_i`、`beta_ij`、`beta_i0` 归一化；`bar u_i G_i(bar n_i)=Lambda_i`；目标代入动态方程后稳态残差接近 0 | B1 |
| C2: 在手稿定理条件下，闭环误差局部指数衰减 | 这是理论主结论，必须用最小数值系统直接验证 | `rho(B)<1`；闭环矩阵 `A=(B^T-I)K-H` 全部特征值实部小于 0；多个目标附近扰动下误差衰减，且数值轨迹与未饱和线性误差系统一致 | B2 |

## Paper Storyline

- Main paper must prove: 单层三区域玩具系统中，静态守恒输出可以构造自由流目标；在 `rho(B)<1` 和未饱和邻域内，闭环误差指数衰减。
- Appendix can support: 采样保持离散实现、步长敏感性、容量和饱和边界扫描。
- Experiments intentionally cut: 多层航路、显式飞行时延、起降场排队、逐目的地组分状态、大规模 MPC、在线重路由、真实城市数据校准。它们会模糊当前理论最小主线。
- Frontier contribution: 本手稿不是 LLM、VLM、Diffusion 或 RL 方法，因此不设置 frontier necessity block。

## Minimal Three-Zone Scenario

### Network

- 单层低空区域: `R={1,2,3}`。
- 邻接支撑: `1-2`、`2-3`。不使用高度层、不使用飞行时延、不使用起降排队。
- 候选路径流:
  - `P1: 1 -> 2 -> 3`, flow `0.4`
  - `P2: 2 -> 3`, flow `0.2`
  - `P3: 1 -> 0`, flow `0.2`, 其中 `0` 表示完成服务并离开动态系统。

### Static Aggregation

| Quantity | Value |
|----------|-------|
| `q^g` | `(0.6, 0.2, 0.0)` |
| `T_12` | `0.4` |
| `T_23` | `0.6` |
| `T_10` | `0.2` |
| `T_30` | `0.6` |
| all other `T_ij` | `0` |
| `Lambda` | `(0.6, 0.6, 0.6)` |
| `beta_12, beta_10` | `2/3, 1/3` |
| `beta_23, beta_20` | `1, 0` |
| `beta_30` | `1` |

The active-region matrix is

```text
B =
[[0, 2/3, 0],
 [0,   0, 1],
 [0,   0, 0]]
```

This matrix is nilpotent, so `rho(B)=0<1`. It is intentionally simple because the first experiment should test the theorem, not a complicated route planner.

### MFD and Control Parameters

- Use the same calibrated single-peaked MFD for all regions:

```text
G_i(n) = 0.3 n (1 - n/20), 0 <= n <= 20
n_i^cr = 10
G_i^max = 1.5
```

- Boundary release margin: `bar u_i=0.6`.
- Target condition: `Lambda_i / bar u_i = 1.0`, hence the free-flow target is the smaller root of `G_i(n)=1.0`:

```text
bar n_i = 4.2265 for i=1,2,3
```

- Takeoff capacities: `bar q^a=(1.0, 0.8, 0.5)`.
- Interface capacities: `C_12=C_23=C_10=C_30=1.2`; unused interfaces may be treated as `infinity`.
- Boundary gains: `kappa=(0.4, 0.4, 0.4)`.
- Takeoff feedback gains: `eta=(0.1, 0.1, 0.0)`. Region 3 has `q_3^g=0`, so its takeoff feedback gain is set to zero as required by the manuscript.
- Denominator guard: `epsilon_i=0.05<G_i(bar n_i)=1.0`.

The expected unsaturated local error matrix is

```text
A = (B^T - I)K - H
  =
[[-0.5,     0,    0],
 [ 0.2667, -0.5,  0],
 [ 0,       0.4, -0.4]]
```

Expected eigenvalues: `(-0.5, -0.5, -0.4)`.

## Experiment Blocks

### Block 1: Three-Zone Static Bridge and Feasibility

- Claim tested: C1.
- Why this block exists: It verifies that the synthetic path flows truly satisfy the assumptions entering the theorem before any ODE simulation is trusted.
- Dataset / split / task: Deterministic synthetic single-layer three-zone path-flow instance above; no train/test split.
- Compared systems: Only the proposed static aggregation pipeline. No baseline is needed for the theorem check.
- Metrics:
  - Static conservation residual: `max_i |q_i^g + sum_j T_ji - sum_j T_ij - T_i0|`.
  - Beta normalization residual: `max_i |sum_j beta_ij + beta_i0 - 1|` for active regions.
  - Target residual: `max_i |bar u_i G_i(bar n_i)-Lambda_i|`.
  - Interface margin: `min_ij (C_ij-T_ij)`.
  - Takeoff margin: `min_i (bar q_i^a-q_i^g)`, and interior check only where `eta_i>0`.
- Setup details:
  - Implement a parameter file or script object containing the exact scenario.
  - Compute `q^g,T,Lambda,beta,B,bar n`.
  - Report all residuals before running dynamics.
- Success criterion:
  - Conservation and normalization residuals `<=1e-10`.
  - Target residual `<=1e-8`.
  - All modeled interface and takeoff margins positive.
  - Region 3 correctly uses `eta_3=0` because `q_3^g=0`.
- Failure interpretation:
  - If this block fails, the experiment does not test the manuscript theorem; fix the static aggregation first.
- Table / figure target:
  - Main paper Table 1: three-zone scenario, feasibility residuals, `rho(B)`.
- Priority: MUST-RUN.

### Block 2: Local Closed-Loop Exponential Stability

- Claim tested: C2.
- Why this block exists: It directly checks the local exponential stability theorem on the smallest nontrivial multi-region system.
- Dataset / split / task: Same three-zone system; initial states are small perturbations around `bar n`.
- Compared systems:
  - Proposed closed-loop ODE with saturation operators.
  - Exact unsaturated linear error system `dot e = A e` as the oracle inside the local neighborhood.
  - Optional open-loop static execution `r_i=q_i^g,z_i=Lambda_i` as a qualitative contrast, not a theorem baseline.
- Metrics:
  - `rho(B)`.
  - Maximum real part of eigenvalues of `A`.
  - `||e(t)||_2 / ||e(0)||_2` at final time.
  - Fitted log-error decay slope on the interval after numerical transients.
  - Saturation fraction for `r_i` and `u_i`.
  - Relative trajectory mismatch between nonlinear saturated implementation and exact linear oracle while unsaturated.
  - Nonnegativity and capacity violations count.
- Setup details:
  - Use ODE integration over `T=20` time units.
  - Use at least 3 deterministic perturbation directions, for example `(+,+,+)`, `(+,-,+)`, `(-,+,-)`, each scaled to at most `10%` of `bar n_i`.
  - Use solver tolerances tight enough that reducing tolerances changes final metrics by less than `1e-3`.
- Success criterion:
  - `rho(B)<1`.
  - `max Re(lambda(A))<0`, expected `-0.4`.
  - No saturation in the local runs.
  - No negative states and no interface capacity violations.
  - Nonlinear implementation matches the exact linear oracle with relative error `<=1e-3` when both are sampled on the same time grid.
  - Final error ratio `<=0.05` for `T=20`.
- Failure interpretation:
  - If spectral checks pass but nonlinear and linear trajectories disagree without saturation, the controller implementation likely has a sign, indexing, or denominator bug.
  - If saturation occurs, the run is outside the theorem's local unsaturated neighborhood and should not be counted as supporting C2.
- Table / figure target:
  - Main paper Figure 1: three regional accumulations converging to `bar n`.
  - Main paper Figure 2: log error norm with expected exponential decay.
  - Main paper Table 2: eigenvalues, final error ratio, saturation fraction, oracle mismatch.
- Priority: MUST-RUN.

### Block 3: Boundary and Falsification Checks

- Claim tested: C3.
- Why this block exists: A convincing validation must show that the checker rejects cases outside the theorem, rather than making every run look successful.
- Dataset / split / task:
  - Stress A, spectral violation: replace the valid flows by a closed cycle `1->2`, `2->3`, `3->1` with no completion flow. This gives a stochastic internal `B` with `rho(B)=1`.
  - Stress B, capacity violation: multiply all valid demands and planned flows by `1.6`, which makes `Lambda_i=0.96` and violates `Lambda_i<bar u_i G_i^max=0.9`.
  - Stress C, far-initial-state saturation: keep the valid static plan but start at a perturbation large enough to trigger `u_i=0` or `u_i=1`.
- Compared systems:
  - Valid theorem instance from Blocks 1 and 2.
  - Each stress instance separately.
- Metrics:
  - Which assumption fails.
  - Whether the checker blocks theorem-support labeling.
  - Saturation fraction and capacity residuals for stress cases.
  - Eigenvalue or spectral-radius diagnostic for the closed-cycle case.
- Setup details:
  - These runs are diagnostic; do not tune them to pass.
  - The expected output is a failure classification, not a performance improvement.
- Success criterion:
  - Spectral violation is flagged before dynamic evidence is interpreted.
  - Capacity violation is flagged before target construction is accepted.
  - Far-initial-state saturation is reported as outside the local theorem conditions.
- Failure interpretation:
  - If any stress case is reported as theorem support, the result-checking pipeline is unsafe.
- Table / figure target:
  - Appendix Table A1: assumption failure matrix.
  - Optional appendix figure: saturated run showing why local theorem conditions matter.
- Priority: MUST-RUN for result integrity, even if the paper only summarizes it briefly.

### Block 4: Sampled Implementation and Numerical Robustness

- Claim tested: C2 support only.
- Why this block exists: The manuscript notes that sampled-hold implementation needs an additional discrete stability check. This block prevents a continuous-time theorem from being overclaimed for a coarse discrete simulator.
- Dataset / split / task: Same valid three-zone instance.
- Compared systems:
  - Continuous ODE solver.
  - Forward-Euler sampled update for `Delta t in {0.05, 0.1, 0.25, 0.5}`.
  - Optional exact matrix exponential update as a reference.
- Metrics:
  - `rho(I+A Delta t)` for Euler.
  - Final error ratio versus continuous solution.
  - Step-size sensitivity of reported decay metrics.
- Setup details:
  - Only needed if the eventual experiment code uses sampled discrete updates.
  - If using a continuous ODE solver only, keep this as appendix or an engineering check.
- Success criterion:
  - The chosen production step size has `rho(I+A Delta t)<1`.
  - Halving the step size changes core metrics by less than `1e-3`.
- Failure interpretation:
  - A coarse unstable step size is a numerical implementation issue, not a violation of the continuous-time theorem.
- Table / figure target:
  - Appendix Table A2.
- Priority: NICE-TO-HAVE unless the simulator is discrete-time.

## Result Inspection Protocol

Every result file should be checked at seven levels before being used in the manuscript.

| Level | Check | Pass Rule |
|-------|-------|-----------|
| L0 Reproducibility | Parameter file, seed or deterministic run ID, solver tolerance, commit or manuscript source recorded | All fields present |
| L1 Static feasibility | Conservation, nonnegativity, beta normalization, active set, inactive-region zero-flow rule | Residual thresholds from Block 1 |
| L2 Target feasibility | MFD target on free-flow branch, `Lambda_i<bar u_i G_i^max`, takeoff and interface margins | All strict margins positive |
| L3 Stability assumptions | `rho(B)<1`, eigenvalues of `A`, correct `eta_i=0` when takeoff interior condition fails | All theorem assumptions pass |
| L4 Dynamic execution | Nonnegative states, no unplanned saturation in local runs, capacities respected | No violations in theorem-support runs |
| L5 Numerical integrity | ODE tolerance sensitivity, analytic linear-oracle mismatch, optional step-size check | Differences below thresholds |
| L6 Reporting safety | Stress cases labeled as assumption failures, not as theorem support | No false positive support labels |

The result checker should emit one final classification per run:

- `SUPPORTS_THEOREM`: all L1 to L5 checks pass for a local valid run.
- `ASSUMPTION_FAILURE`: static, capacity, spectral, or target condition fails.
- `OUTSIDE_LOCAL_REGION`: theorem assumptions hold at the target but trajectory triggers saturation or leaves the local neighborhood.
- `NUMERICAL_UNRELIABLE`: theory assumptions hold but solver or implementation checks fail.

## Risks and Mitigations

- Risk: The experiment accidentally validates only a coding artifact, not the theorem.
- Mitigation: Run Block 1 and Block 2 prechecks before interpreting trajectories; compare nonlinear implementation against the exact linear oracle.

- Risk: The perturbation leaves the local unsaturated neighborhood.
- Mitigation: Start with `5%` to `10%` target-scale perturbations; report saturation fraction and classify saturated trajectories as `OUTSIDE_LOCAL_REGION`.

- Risk: `B` is constructed with the wrong orientation.
- Mitigation: Explicitly test that `B[i,j]=beta_ij` and the error system uses `B^T`; include a hand-computed expected `A`.

- Risk: The free-flow target uses the congested root of the quadratic MFD.
- Mitigation: Enforce `bar n_i<n_i^cr` and verify `G_i` is increasing at `bar n_i`.

- Risk: Stress cases are visually interesting and get mistaken for negative evidence against the theorem.
- Mitigation: Keep each stress run's assumption-failure label in the output table.
